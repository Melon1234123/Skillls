# 黑底白字 · 笨拙手写笔记

把用户提供的图片做成可读、但不精致的手写笔记。字体粗糙程度和内容准确性是两个独立维度：可以把字写丑，不能因此丢字、改公式或改箭头。

## 判断用户要改什么

- 明确用户给的是编辑目标，还是仅供模仿的风格参考。多张图按上传顺序编号。
- 默认保留原文语言、题号和答案；只做已请求的视觉修改。用户没有要求黑底白字时，不强行改变配色。
- “像小学生”强调字形不均衡、笔画控制不熟练；不要自动美化成圆润可爱的手写字体。
- “太美了 / 再丑一点”是加重潦草程度的反馈。沿用已经核对过的版本，增加字高、宽窄、倾斜、基线和笔压差异；通常无需再次改布局。
- 用户明确要重排时，先规划阅读顺序与留白；后续风格调整保留布局，减少内容漂移。删去工具栏、状态栏等截图界面，但保留它们附近的正文。
- 用当前上下文决定风格，不为普通美术选择反复询问。确实缺图或关键字无法辨认时才索要补充信息。

## 工具与输入

使用宿主提供的图片编辑工具；Codex 中优先内置 imagegen，遵守其当前工具说明和可用的 imagegen skill。不要硬编码某次会话的工具名称、调用参数、缓存路径或模型版本。

先查看每张编辑目标。可用本地路径时逐张引用；工具只支持会话图片时，按实际接口引用对应图片。把第二张风格图明确标成“仅参考字迹”，禁止复制它的题目。

若当前环境没有可用的图片编辑能力，明确说明限制并提供提示词。只有用户选择了相应方案时才使用需付费或密钥的 API；不要静默安装依赖、提取凭据或切换服务。不要用代码重绘或简单反色冒充已完成的手写风格编辑。

## 先锁定内容

密集页面先做简短的内容清单，留在本地工作记录中，不把清单额外印到成图：

- 逐行文字、数字、公式、集合元素、上下标、表格行列与空白单元格。
- 每幅图的节点名、节点数量、起点、单圈/双圈、每条边的起点、终点、标签、自环。
- 明确区分容易混淆的字形，如 z/2、q/g、0/o、1/l、ε/∅。
- 原图中 a/b 与 0/1 不一致、缺失某个转移等问题，不因推导得出“应该如此”而擅自改答案。记录不确定项，避免把猜测声称为忠实转录。

清单不必复述到每次生成提示词。对清晰且已核验的输入，优先做局部风格编辑；只有小字难认时才附必要的精确转录。

## 调节“丑”的程度

| 程度 | 外观 | 应避免 |
| --- | --- | --- |
| 自然稚拙 | 不均匀字形、轻微偏斜、略笨拙的笔画 | 书法感、可爱字体、均匀圆润字形 |
| 明显潦草 | 高低错落、宽窄不齐、间距不一、钝短笔画、歪圈和徒手表线 | 所有线条只套同一种抖动、机械一致的字 |
| 很笨拙但可读 | 更不平衡的字部件、局部拥挤、粗细和倾角明显变化 | 乱码、擦掉标签、额外涂改答案、让图线穿过文字 |

用 [提示词模板](references/prompts.md) 组装本次请求。黑底白字模式采用纯黑底和白色笔迹，不添加黑板纹理、装饰、照片透视或新标题。圆圈可歪，双圈仍须清楚地有两圈；箭头可抖，方向仍须明确。

多页可在工具支持时独立生成。首次风格不明确时，可先用内容较少的一页校准，再将同一风格应用到其余页；这是内部质量检查，不是必须等用户批准的关卡。一次请求应交付所有目标页。

## 核对与小范围修复

每张输出都看图检查，使用 [内容核对表](references/content-check.md)。提示词写了“保留内容”并不能证明实际保留了。

本工作流容易出现的回归：

- 同一个状态被重复绘制，或状态整块遗漏。
- 双圈变成单圈，尤其是粗糙化以后。
- 箭头尖消失、反向或多一个尖，回边变成双向边。
- 自环的 0/1、ε、表格集合中的元素被漏掉或重复。
- 字体更乱后，上下标和相邻标签粘连。

发现差异时，对已生成图只修指定小区域。写清位置、当前错误、期望变化和其余内容保持不变。修完再次查看局部和周围，避免修箭头时又弄丢自环标签。

同一错误经过两次局部修复仍存在时，停止盲目重复：回到最近可核验版本，缩小变更范围再决定是否可交付；如仍无法可靠保留内容，明确标注问题并保留原图。不要用无限重生成代替验证，也不要把未核对的图说成内容完全一致。

## 保存与交付

- 保留原图和旧版，输出写到独立目录。多页按原顺序用 01、02 等稳定编号。
- 保存所有最终图片，必要时打包 ZIP；确认压缩包页数、顺序和实际文件相符。
- 图片生成、文件复制与压缩分别处理；没有必要为了打包再重编码图片。
- 展示最终图片或提供可打开的图片/压缩包链接。简短说明风格变化与任何尚未解决的内容差异。
- 不因本 skill 自动公开用户图片、上传 GitHub 或提交作业。这些外部操作需要用户在当前任务中明确提出。
